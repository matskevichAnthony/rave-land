# Пайплайн: картинка → 3D-персонаж с нормальной анимацией

Это ГЛАВНЫЙ рабочий документ. Отвечает на один вопрос: у меня есть (или будет) картинка
персонажа — как реально, просто и бесплатно получить из неё анимированную модель в игре.
Факты и лицензии — в `docs/FINDINGS.md` и `docs/research/3d-services-2026.md`.

Целевая эстетика: low-poly хоррор (FEAR, Cry of Fear, старые Resident Evil) —
детализация живёт в ТЕКСТУРЕ, не в геометрии. Бюджеты: NPC 2–5 тыс. треугольников,
главные персонажи 8–15 тыс.

---

## 0. Правила генерации ИЗОБРАЖЕНИЯ (шаг «я иду в любой ИИ»)

Качество 3D-результата на 80% решается картинкой. Шаблон промпта:

```
full body character, standing in T-pose, arms straight out to the sides,
front view, feet shoulder-width apart, neutral facial expression,
low-poly PS1/PS2 survival horror style (Cry of Fear, old Resident Evil),
chunky simplified geometry, painted texture detail, muted desaturated palette,
[ОПИСАНИЕ ПЕРСОНАЖА: berlin raver in dark hoodie, cargo pants, ...],
flat uniform light gray background, even studio lighting, no shadows on background,
single character, nothing cropped, entire body visible including feet
```

Жёсткие правила (нарушение = потерянные кредиты генератора):
1. **T-поза или A-поза.** Динамичная поза = мусорный меш и невозможный авториг.
2. **Однотонный нейтральный фон** (светло-серый). Не прозрачный градиент, не сцена.
3. **Всё тело в кадре**, включая ступни. Обрезанные ноги = генератор их выдумает.
4. **Ровный свет без теней.** Драматичный свет запекается в текстуру грязными пятнами.
5. **Избегать:** мех, прозрачные ткани, частицы/дым, тонкие свисающие ремни, оружие
   в руках (генерировать отдельно), очень тёмный «чёрный на чёрном» — генераторы
   теряют силуэт. Тёмного персонажа рисовать на СВЕТЛОМ фоне.
6. Разрешение 1024×1024+. Если ИИ умеет — сразу второй ракурс (спина) тем же сидом:
   Tripo/Hunyuan принимают мультивью и дают заметно лучший зад модели.

## 1. Дерево решений для агента

```
Картинка персонажа получена
│
├─ Требование «всё локально, без облака»?
│   │
│   ├─ Есть NVIDIA ≥6 ГБ VRAM (второй ноутбук, если F-016 подтвердится)
│   │                                  → МАРШРУТ L2 (Hunyuan3D-2GP / Stable Fast 3D)
│   │
│   └─ Слабый ПК, CPU-only / без NVIDIA → МАРШРУТ L1 (TripoSR на CPU)
│
├─ Нужен ЧЕЛОВЕКОПОДОБНЫЙ персонаж (2 руки, 2 ноги)?
│   │
│   ├─ Есть кредиты Tripo (200/мес)?  → МАРШРУТ B (самый короткий: всё в одном)
│   │
│   └─ Кредитов нет / кончились      → МАРШРУТ A (основной, $0, проверен дважды)
│
└─ Существо / нестандартная анатомия → МАРШРУТ C (Mesh2Motion или Anything World)
```

Правило: **не изобретать новые пути, пока эти не упёрлись в стену.**

## 2. МАРШРУТ A — основной, $0, полностью проверен (оба персонажа игры сделаны им)

Меш из бесплатной HF-очереди, риг и анимации свои. Единственный маршрут,
где каждый шаг уже выполнялся в этом репозитории.

| Шаг | Инструмент | Статус |
|---|---|---|
| 1. Меш из картинки | TRELLIS HF Space (или Hunyuan3D Space) через `gradio_client`; вручную — браузером | ✅ проверен |
| 2. Даунскейл до бюджета | Blender decimate headless / gltfpack | ✅ проверен |
| 3. Авториг 17 костей | `_other/auto-rig/step1_rig.py` + `step2_weights.py` (Blender headless) | ✅ проверен ×2 |
| 4. Анимации (mocap) | `tools/anim/bvh2clip <clip.bvh> <Name> --rig-dir <риг>` | ✅ проверен, 7 клипов |
| 5. Постобработка | `tools/postprocess.mjs` (webp + квантизация) | ✅ проверен |
| 6. В игру | GLB в `public/assets/models/`, имена клипов под регулярки `src/npc/gltf-character.js` | ✅ проверен |

**Откуда «нормальные» анимации для шага 4** (НЕ самопальные процедурные):
- **Mesh2Motion (mesh2motion.org)** — 150+ клипов CC0, скачиваются с любым скелетом. Приоритет №1.
- **Quaternius Universal Animation Library** — CC0 игровые клипы. Приоритет №2.
- **CMU Mocap** — бесплатно вкл. коммерцию; нужен новый bone map в `BONE_MAPS` (`tools/anim/retarget.py`), техника переноса описана в F-012.
- Bandai (текущие клипы) — только пока проект некоммерческий (F-004).

Ограничение маршрута: HF Space — очередь, бывают падения. Это цена $0.

## 3. МАРШРУТ B — самый короткий (Tripo: меш+риг+анимации в одном сервисе)

Когда важна скорость и есть кредиты (200/мес ≈ 8 моделей, сгорают):

1. Картинка → Tripo (Studio или API): image-to-3D **с включённым ригом и базовыми анимациями**.
2. Выход — готовый GLB со скелетом и walk/run/idle. В бюджет полигонов — ретопология там же.
3. Не хватает клипов (танцы!) → дотаргетить нашим `bvh2clip` на скелет Tripo
   (новый bone map) или прогнать через Mixamo.
4. `tools/postprocess.mjs` → в игру.

Нюансы: free-результаты публичны, CC BY 4.0 (⚠️ сверить некоммерческую оговорку ToS перед
коммерцией — F-005); стандартный скелет Tripo ≠ наш 17-костный — их не смешивать в одном GLB.

## 4. МАРШРУТ C — существа и страховка

- **Mesh2Motion** (браузер, без GPU): загрузить меш → выбрать скелет (гуманоид/квадропед/
  существо) → авториг → выбрать клипы из CC0-библиотеки → экспорт GLB. Самый простой
  путь «нормальной» анимации вообще без нашего кода.
- **Anything World / Animate Anything**: единственный авториг существ с REST API — если
  Mesh2Motion не справился с анатомией.
- **Mixamo** (страховка для гуманоидов): `_other/character-rigging/mixamo-ready.fbx` уже
  подготовлен (F-013). Огромная библиотека, но только браузер, без API.

## 4.5. МАРШРУТЫ L — полностью локальные (без облака вообще)

Отличаются от A только **шагом 1** (меш из картинки). Шаги 2–6 маршрута A и так
локальные (Blender headless, свой авториг, `bvh2clip` с локальными BVH, postprocess) —
менять ничего не нужно. Скачанные заранее CC0 BVH-клипы (Mesh2Motion/Quaternius/CMU)
лежат оффлайн — интернет после этого не нужен в принципе.

### L1 — самый слабый ПК (CPU-only, без NVIDIA — текущая машина)

- **TripoSR** (open source, MIT) — единственная жизнеспособная image→mesh модель на CPU.
  Умеренная RAM, минуты на модель. Без текстурной покраски — только vertex color /
  простая проекция, поэтому текстуру добиваем проекцией исходной картинки в Blender
  (Smart UV + project from view) — для PS1/PS2-эстетики этого достаточно.
- Качество заметно ниже TRELLIS/Hunyuan: годится для фоновых NPC (2–5 тыс. треугольников
  после decimate), для главных персонажей — лучше маршрут A/B, когда облако доступно.
- Аварийные CPU-варианты ещё ниже качеством: Shap-E, Point-E — только черновики-болванки.

### L2 — второй ноутбук (16 ГБ RAM + NVIDIA, ждёт F-016: узнать VRAM)

При дискретной NVIDIA ≥6 ГБ VRAM:

- **Hunyuan3D-2GP** («GPU poor»-форк) — лучшее локальное качество формы+текстуры при
  6 ГБ VRAM; профили low-RAM/low-VRAM. Полный официальный Hunyuan — НЕ ставить
  (до 24,5 ГБ на shape+texture).
- **Stable Fast 3D** (~6 ГБ VRAM) — быстрый GLB с UV и текстурой, проще в установке;
  хорош как первый кандидат, Hunyuan3D-2GP — как качественный.
- ComfyUI-TRELLIS2 на 6–8 ГБ — нестабильный эксперимент, не основной путь.
- Если VRAM <4 ГБ или встройка — L2 не существует, действует вывод F-001: облако + L1.

Риг и анимации в L1/L2 те же локальные: свой авториг → `bvh2clip` с оффлайн-BVH.

## 5. Роль терминального агента (раннбук)

Агент получает: путь к картинке + задачу («новый NPC», «замена анимаций», «существо»).

1. Проверить картинку по правилам раздела 0 (поза, фон, обрезка). Не проходит — сначала
   попросить перегенерацию, НЕ жечь кредиты генератора 3D.
2. Выбрать маршрут по дереву раздела 1.
3. Идти по шагам маршрута; автоматизация в порядке: API/`gradio_client` → Playwright →
   ручная пауза только на login/CAPTCHA (правило из каталога сервисов, раздел 6).
4. Каждый готовый персонаж: постобработка → проверка в браузере (страница /characters.html
   и спавн в игре) → отдельный коммит.
4b. **Обязательно заполнить `provenance`** в записи NPC (`public/world.json`):
   `model` (кто сгенерировал меш: TRELLIS Space / Tripo / TripoSR local / ...),
   `rig` (свой авториг / Tripo / Mesh2Motion / Mixamo),
   `animations` (источник клипов и лицензия). Это выводится в карточке NPC в игре —
   так визуально сравниваем провайдеров между собой.
5. Любой новый факт/грабли — записью в `docs/FINDINGS.md` (F-NNN), закрытие — коммитом.

## 6. Открытые вопросы

- **F-016**: второй ноутбук (16 ГБ RAM, NVIDIA) — выяснить модель GPU и VRAM. Если это
  дискретная карта ≥6 ГБ VRAM, локально заводится Hunyuan3D-2GP и маршрут A теряет
  зависимость от HF-очереди. Если встройка/MX <4 ГБ — ничего не меняется.
- **F-007**: прогнать mocap на bold-raver (`--rig-dir` уже готов).
- Пополнить пакет клипов из Mesh2Motion (hit, fall, interact) — заодно старт замены Bandai (F-004).
