# Пайплайн: картинка → 3D-персонаж с нормальной анимацией

## Куда всё это идёт (главная цель конвейера)

Персонажи, мир и даже игра это расходный материал, а конвейер нет. Цель: **любая
сгенерированная модель после рига получает готовую библиотеку движений и всю механику
оружия бесплатно**, без ручной работы на каждого персонажа. Тогда стоимость нового
персонажа падает до стоимости картинки, и это переносится в любой следующий проект,
потому что ни одна часть конвейера не знает про конкретный мир.

Быстрая дорожка выглядит так:

```
картинка -> меш (облачный или локальный маршрут) -> риг по канону
   -> персонаж СРАЗУ умеет: ходить, бегать, прыгать, держать четыре ствола,
      стрелять с отдачей, приседать, танцевать
```

Работает это потому, что San Andreas сама устроена как переносимый конвейер: анимации не
принадлежат модели, клипы стрельбы частичные и накладываются поверх любой походки, а
поведение оружия лежит данными. Подробности в F-043, F-048, F-049.

Что для этого обязательно соблюдать:

1. **Rest-поза одинаковая у всех.** Клип хранит повороты относительно неё, поэтому своя
   rest-поза у каждого персонажа означает непереносимые клипы (F-044). Направления костей
   заданы конвенцией в `rig_lib.CANONICAL_DIRECTIONS`, от меша берутся только длины.
2. **Игровой код не знает имён костей и клипов.** Всё через реестр профилей
   `src/anim/skeleton-profile.js` и каталог оружия `src/combat/weapons.json`, который
   генерируется из игровых данных, а не пишется руками. Новый источник ассетов это одна
   запись, а не правка логики.
3. **Ассеты подменяемы.** Rockstar годится для приватного прототипа, не для публикации
   (F-041). Замена на CC0 не должна менять ни строки игрового кода, и сейчас не меняет.

Это ГЛАВНЫЙ рабочий документ. Отвечает на один вопрос: у меня есть (или будет) картинка
персонажа — как реально, просто и бесплатно получить из неё анимированную модель в игре.
Факты и лицензии — в `docs/FINDINGS.md` и `docs/research/3d-services-2026.md`.

Целевая эстетика: low-poly хоррор (FEAR, Cry of Fear, старые Resident Evil) —
детализация живёт в ТЕКСТУРЕ, не в геометрии. Бюджеты: NPC 2–5 тыс. треугольников,
главные персонажи 8–15 тыс.

## 0. Правила генерации ИЗОБРАЖЕНИЯ (шаг «я иду в любой ИИ»)

Качество 3D-результата на 80% решается картинкой. Шаблон промпта:

```
full body character, standing in T-pose, arms straight out to the sides,
front view, feet shoulder-width apart, neutral facial expression,
low-poly PS1/PS2 survival horror style (Cry of Fear, old Resident Evil),
chunky simplified geometry, painted texture detail, muted desaturated palette,
[ОПИСАНИЕ ПЕРСОНАЖА: berlin raver in dark hoodie, cargo pants, ...],
flat uniform light gray background, even studio lighting, no shadows on background,
single character, nothing cropped, entire body visible including feet
```

Жёсткие правила (нарушение = потерянные кредиты генератора):
1. **T-поза или A-поза.** Динамичная поза = мусорный меш и невозможный авториг.
2. **Однотонный нейтральный фон** (светло-серый). Не прозрачный градиент, не сцена.
3. **Всё тело в кадре**, включая ступни. Обрезанные ноги = генератор их выдумает.
4. **Ровный свет без теней.** Драматичный свет запекается в текстуру грязными пятнами.
5. **Избегать:** мех, прозрачные ткани, частицы/дым, тонкие свисающие ремни, оружие
   в руках (генерировать отдельно), очень тёмный «чёрный на чёрном» — генераторы
   теряют силуэт. Тёмного персонажа рисовать на СВЕТЛОМ фоне.
6. Разрешение 1024×1024+. Если ИИ умеет — сразу второй ракурс (спина) тем же сидом:
   Tripo/Hunyuan принимают мультивью и дают заметно лучший зад модели.

## 1. Дерево решений для агента

```
Нужен ПРОП, а не персонаж (колонка, ящик, бочка, ограждение)?
│                                     → РАЗДЕЛ 4.6 (скриптом, без ИИ и без облака)
│
Картинка персонажа получена
│
├─ Требование «всё локально, без облака»?
│   │
│   ├─ Есть NVIDIA ≥6 ГБ VRAM (второй ноутбук, если F-016 подтвердится)
│   │                                  → МАРШРУТ L2 (Hunyuan3D-2GP / Stable Fast 3D)
│   │
│   └─ Слабый ПК, CPU-only / без NVIDIA → МАРШРУТ L1 (TripoSR на CPU)
│
├─ Нужен ЧЕЛОВЕКОПОДОБНЫЙ персонаж (2 руки, 2 ноги)?
│   │
│   ├─ Есть кредиты Tripo (200/мес)?  → МАРШРУТ B (самый короткий: всё в одном)
│   │
│   └─ Кредитов нет / кончились      → МАРШРУТ A (основной, $0, проверен дважды)
│
└─ Существо / нестандартная анатомия → МАРШРУТ C (Mesh2Motion или Anything World)
```

Правило: **не изобретать новые пути, пока эти не упёрлись в стену.**

## 2. МАРШРУТ A — основной, $0, полностью проверен (оба персонажа игры сделаны им)

Меш из бесплатной HF-очереди, риг и анимации свои. Единственный маршрут,
где каждый шаг уже выполнялся в этом репозитории.

| Шаг | Инструмент | Статус |
|---|---|---|
| 1. Меш из картинки | TRELLIS HF Space (или Hunyuan3D Space) через `gradio_client`; вручную — браузером | ✅ проверен |
| 2. Даунскейл до бюджета | Blender decimate headless / gltfpack | ✅ проверен |
| 3. Авториг 17 костей | `_other/auto-rig/step1_rig.py` + `step2_weights.py` (Blender headless) | ✅ проверен ×2 |
| 4. Анимации (mocap) | `tools/anim/bvh2clip <clip.bvh> <Name> --rig-dir <риг>` | ✅ проверен, 7 клипов |
| 5. Постобработка | `tools/postprocess.mjs` (webp + квантизация) | ✅ проверен |
| 6. В игру | GLB в `public/assets/models/`, имена клипов под регулярки `src/npc/gltf-character.js` | ✅ проверен |

**Откуда «нормальные» анимации для шага 4** (НЕ самопальные процедурные):
- **Mesh2Motion (mesh2motion.org)** — 150+ клипов CC0, скачиваются с любым скелетом. Приоритет №1.
- **Quaternius Universal Animation Library** — CC0 игровые клипы. Приоритет №2.
- **CMU Mocap** — бесплатно вкл. коммерцию; нужен новый bone map в `BONE_MAPS` (`tools/anim/retarget.py`), техника переноса описана в F-012.
- Bandai (текущие клипы) — только пока проект некоммерческий (F-004).

Ограничение маршрута: HF Space — очередь, бывают падения. Это цена $0.

## 3. МАРШРУТ B — самый короткий (Tripo: меш+риг+анимации в одном сервисе)

Когда важна скорость и есть кредиты (200/мес ≈ 8 моделей, сгорают):

1. Картинка → Tripo (Studio или API): image-to-3D **с включённым ригом и базовыми анимациями**.
2. Выход — готовый GLB со скелетом и walk/run/idle. В бюджет полигонов — ретопология там же.
3. Не хватает клипов (танцы!) → дотаргетить нашим `bvh2clip` на скелет Tripo
   (новый bone map) или прогнать через Mixamo.
4. `tools/postprocess.mjs` → в игру.

Нюансы: free-результаты публичны, CC BY 4.0 (⚠️ сверить некоммерческую оговорку ToS перед
коммерцией — F-005); стандартный скелет Tripo ≠ наш 17-костный — их не смешивать в одном GLB.

## 4. МАРШРУТ C — существа и страховка

- **Mesh2Motion** (браузер, без GPU): загрузить меш → выбрать скелет (гуманоид/квадропед/
  существо) → авториг → выбрать клипы из CC0-библиотеки → экспорт GLB. Самый простой
  путь «нормальной» анимации вообще без нашего кода.
- **Anything World / Animate Anything**: единственный авториг существ с REST API — если
  Mesh2Motion не справился с анатомией.
- **Mixamo** (страховка для гуманоидов): `_other/character-rigging/mixamo-ready.fbx` уже
  подготовлен (F-013). Огромная библиотека, но только браузер, без API.

## 4.5. МАРШРУТЫ L — полностью локальные (без облака вообще)

Отличаются от A только **шагом 1** (меш из картинки). Шаги 2–6 маршрута A и так
локальные (Blender headless, свой авториг, `bvh2clip` с локальными BVH, postprocess) —
менять ничего не нужно. Скачанные заранее CC0 BVH-клипы (Mesh2Motion/Quaternius/CMU)
лежат оффлайн — интернет после этого не нужен в принципе.

### L1: самый слабый ПК (CPU-only, без NVIDIA, текущая машина)

**Проверено запуском, не по слухам** (замеры и грабли в F-001, качество в F-019).
**TripoSR** (open source, MIT) на CPU работает: около 45 секунд на модель, пик 2.2 ГБ RSS.
Штатный `TripoSR/run.py` этого не переживает (аллоцирует веса дважды, 3.4 ГБ), поэтому
запускать надо низкопамятную обёртку:

```bash
cd _other/local-gen
HF_HOME=$PWD/weights ./venv/bin/python ../../tools/gen/triposr_local.py \
    <картинка> out/<имя>.glb --mc-resolution 256
```

Свободной памяти нужно около 2.5 ГБ, то есть перед запуском закрыть браузер. Сторож памяти
встроен в скрипт и включён всегда: прогон обрывается сам, если MemAvailable проваливается
ниже порога (`--memory-floor`, в МБ), чтобы машина не ушла в OOM.

- Выход несёт вершинные цвета, без UV и текстуры. Текстуру добиваем проекцией исходной
  картинки в Blender (Smart UV plus project from view), для PS1/PS2-эстетики этого хватает.
- Полигонаж сырого меша 20-84 тыс. треугольников, decimate до бюджета обязателен.
- Качество решает поза на входе, а не сама модель. На картинке в T-позе меш выходит
  топологической сферой: руки отделены по всей длине, кисти торчат, ноги разделены до
  ботинок, читаются капюшон и лицо. На той же модели в idle-позе получался ком со
  сросшимися конечностями. Замер и цифры в F-024, поэтому правила раздела 0 тут не
  формальность, а разница между рабочим мешем и мусором.
- Годится на дальнюю и среднюю дистанцию: толпа, силуэты у бара. На крупный план нет,
  потому что нет текстуры и UV, а спина выдумана. Для героя в кадре брать маршрут A или B.
- Shap-E и Point-E не проверялись и не нужны: TripoSR работает, а по качеству они заведомо
  ниже. Смысл в них появится, только если TripoSR перестанет запускаться.

### L2 — второй ноутбук (16 ГБ RAM + NVIDIA, ждёт F-016: узнать VRAM)

При дискретной NVIDIA ≥6 ГБ VRAM:

- **Hunyuan3D-2GP** («GPU poor»-форк) — лучшее локальное качество формы+текстуры при
  6 ГБ VRAM; профили low-RAM/low-VRAM. Полный официальный Hunyuan — НЕ ставить
  (до 24,5 ГБ на shape+texture).
- **Stable Fast 3D** (~6 ГБ VRAM) — быстрый GLB с UV и текстурой, проще в установке;
  хорош как первый кандидат, Hunyuan3D-2GP — как качественный.
- ComfyUI-TRELLIS2 на 6–8 ГБ — нестабильный эксперимент, не основной путь.
- Если VRAM <4 ГБ или встройка — L2 не существует, действует вывод F-001: облако + L1.

Риг и анимации в L1/L2 те же локальные: свой авториг → `bvh2clip` с оффлайн-BVH.

## 4.55. Как подключить новый источник анимаций

Схема одна на всех, ядро ретаргета при этом не трогается (F-036):

```
источник -> адаптер в BVH -> retarget.py (BONE_MAPS) -> bvh2clip -> GLB
```

1. Если источник уже BVH, адаптер не нужен, шаг пропускается.
2. Иначе пишется конвертер: разбор формата в `tools/gta/` (или в соседнем каталоге, названном
   по источнику), сборка BVH через готовый `tools/anim/bvh_writer.py`, которому отдаются дерево
   костей `Joint` и кейфреймы. Он сам ресемплит на равномерный fps, переводит в сантиметры и в
   оси, которые ждёт импортёр Blender. Готовый пример адаптера: `tools/anim/ifp2bvh.py`.
3. В `BONE_MAPS` (`tools/anim/retarget.py`) добавляется запись `'имя_скелета'`: на каждую из
   наших 17 костей пара `(сустав источника, дочерний сустав для направления)`.
4. Всё. Карта выбирается автоматически по именам суставов во входном BVH, команда запуска не
   меняется: `tools/anim/bvh2clip <clip.bvh> <ИмяКлипа> [--rig-dir <риг>]`.

Результат проверять замером, а не логом: дрейф таза за клип должен быть около нуля (клипы в
игре стоят на месте), нижняя точка стопы сравнима с уже принятыми клипами. При сломанном
источнике логи выглядят совершенно здоровыми, это доказано на F-038.

## 4.56. Источник: GTA San Andreas

Формат разобран целиком, справочник в `docs/research/gta-sa-ifp.md`, находки в F-037 и F-039.

```bash
python3 tools/gta/ifp.py "<файл.ifp>" --list          # что лежит внутри пакета
python3 tools/anim/ifp2bvh.py "<файл.ifp>" WALK_civi -o /tmp/walk.bvh
tools/anim/bvh2clip /tmp/walk.bvh GtaWalk             # карта gta_sa выберется сама
```

Что откуда брать: `ped.ifp` лежит в установленной игре россыпью и даёт стойки, походки и бег.
**Танцев в нём нет ни одного**, они в `anim/anim.img` (`DANCING.ifp`, `WOP.ifp`,
`RUNNINGMAN.ifp`, `GFUNK.ifp`), архив распаковывается через `tools/gta/img.py`.

Модели педов (`.dff` вместе с `.txd`) читаются через `tools/gta/dff.py` и `tools/gta/txd.py`.
У них родной скелет SA, поэтому анимации из `.ifp` ложатся на них напрямую по `bone id`, без
ретаргета вообще. Оттуда же берётся точная rest-поза скелета для таблицы `SA_SKELETON` в
`ifp2bvh.py`.

Лицензия жёстче, чем у остальных источников: локальный прототип можно, публикация нельзя,
подробности в F-041.

## 4.6. Пропы: отдельная и гораздо более простая задача

Проп (колонка, стек динамиков, ящик, бочка, ограждение, барная стойка, мусор, знак) это не
персонаж. У него нет скелета, весов, анатомии и анимаций, поэтому шаги 3 и 4 маршрута A
для него просто не существуют. Остаётся только получить меш, и здесь короткий путь другой.

**По умолчанию: процедурно, скриптом.** Геометрия рейв-сцены коробочно-цилиндрическая,
и скрипт делает её точнее и дешевле нейросети:

```bash
BLENDER=_other/auto-rig/blender-4.2.9-linux-x64/blender
$BLENDER --background --python tools/gen/props.py -- --prop all \
    --out-dir public/assets/models/props
$BLENDER --background --python tools/gen/props.py -- --prop crate \
    --out public/assets/models/props/crate.glb --seed 7 --render crate.png
```

В библиотеке 14 типов: стек колонок, ящик, бочка, ограждение, барная стойка, ферма со светом,
прожектор на стойке, куча мусора, указатель, поддон, урна, граффити-щит, катушка кабеля,
биотуалет. Сид меняет пропорции и оттенки, так что из одного билдера получается серия
непохожих экземпляров. На всю библиотеку 2 940 треугольников и 229 КБ, самый тяжёлый проп это
ферма (600 треугольников, 43 КБ). Начало координат в центре подошвы, палитра взята из палитры
игры, постобработка не нужна.
Новый проп добавляется функцией-билдером и строкой в `PROPS`. Скрипт заодно пишет
`public/assets/models/props/manifest.json`, из которого страница `/props.html` берёт список,
поэтому новый проп появляется на странице сам.

**Генератор мешей звать только на сложную нерегулярную форму**, где параметризация дороже
картинки: куча мусора, разбитая техника, органика. Тогда работает тот же маршрут A или L1,
что и для персонажей, но без рига: картинка, меш, decimate, `postprocess.mjs`. Пропы у
TripoSR выходят заметно лучше персонажей (F-019), так что локальный путь для них рабочий.

В мир проп кладётся обычной моделью в `public/world.json`, коллайдер считается по bbox:

```json
{ "id": "crate-1", "type": "model", "src": "assets/models/props/crate.glb",
  "position": [4, null, -6], "rotation": [0, 0.4, 0], "scale": [1, 1, 1] }
```

## 5. Роль терминального агента (раннбук)

Агент получает: путь к картинке + задачу («новый NPC», «замена анимаций», «существо»).

1. Проверить картинку по правилам раздела 0 (поза, фон, обрезка). Не проходит — сначала
   попросить перегенерацию, НЕ жечь кредиты генератора 3D.
2. Выбрать маршрут по дереву раздела 1.
3. Идти по шагам маршрута; автоматизация в порядке: API/`gradio_client` → Playwright →
   ручная пауза только на login/CAPTCHA (правило из каталога сервисов, раздел 6).
4. Каждый готовый персонаж: постобработка → проверка в браузере (страница /characters.html
   и спавн в игре) → отдельный коммит.
4b. **Обязательно заполнить `provenance`** в записи NPC (`public/world.json`):
   `model` (кто сгенерировал меш: TRELLIS Space / Tripo / TripoSR local / ...),
   `rig` (свой авториг / Tripo / Mesh2Motion / Mixamo),
   `animations` (источник клипов и лицензия). Это выводится в карточке NPC в игре —
   так визуально сравниваем провайдеров между собой.
5. Любой новый факт/грабли — записью в `docs/FINDINGS.md` (F-NNN), закрытие — коммитом.

## 6. Открытые вопросы

- **F-016**: второй ноутбук (16 ГБ RAM, NVIDIA) — выяснить модель GPU и VRAM. Если это
  дискретная карта ≥6 ГБ VRAM, локально заводится Hunyuan3D-2GP и маршрут A теряет
  зависимость от HF-очереди. Если встройка/MX <4 ГБ — ничего не меняется.
- **F-007**: прогнать mocap на bold-raver (`--rig-dir` уже готов).
- Пополнить пакет клипов из Mesh2Motion (hit, fall, interact) — заодно старт замены Bandai (F-004).
