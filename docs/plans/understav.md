# Сцена UNDERSTAV: контракт модулей

Промо-сцена тусовки UNDERSTAV живёт отдельной страницей `understav.html` и собирается из
четырёх независимых модулей. Это первая проверка доктрины из `docs/plans/world-engine.md`
на живом задании: сцена это данные плюс сид, а не расстановка руками.

## Что снимаем

Лайнап, дата, тэглайн и сид лежат в `public/understav.json` и ни одним модулем не
хардкодятся: порядок имён на афише это порядок в `lineup`.

Стиль: индастриал-готика, трип. Не красный камень с драконами, как у соседей по афишам,
а холодный бетон и железо собора, прожжённое углями.

## Общее для всех модулей

- Палитра, бюджет кадра и темп: `src/understav/palette.js`. Своих цветов не заводить.
- Случайность: только `createRandom(seed)` из `src/understav/random.js`. `Math.random`
  в сцене запрещён, иначе дубль невоспроизводим.
- Ассеты San Andreas (`gta-*.glb`, звуки, анимации) в этой сцене запрещены: промо
  реального события не может содержать чужой контент. Геометрия либо процедурная,
  либо из `public/assets/generated` и `public/assets/models/props`.
- Ничего не грузится из интернета: страницу снимают офлайн.
- Только vanilla JS и `three` из зависимостей проекта.

## Бюджет кадра

`FRAME_BUDGET` в палитре: до 140 вызовов отрисовки, до 400 000 треугольников, до 6
источников света, цель 60 кадров в секунду при 1080p. Одинаковые объекты рисуются
инстансингом (`THREE.InstancedMesh`), а не десятками мешей.

## Модули и их границы

Каждый файл принадлежит ровно одному модулю, чужие файлы не правятся.

### 1. Сцена и свет: `src/understav/stage.js`, `src/understav/architecture.js`

```js
createStage({ mount }) -> {
  renderer, scene, camera,
  resize(width, height),
  update(dt, elapsed),
}

createArchitecture({ rng }) -> {
  group,              // THREE.Group, ставится в сцену вызывающим
  update(elapsed),
  bounds: { radius, height },   // габариты в метрах, по ним ставят камеру и текст
}
```

### 2. Типографика: `src/understav/type.js`

```js
createTypography({ event, rng, bounds }) -> {
  group,
  setDaysLeft(days),
  update(dt, elapsed),
}
```

Буквы это предметы внутри сцены: отбрасывают тень, перекрываются геометрией, попадают
в свечение. Лайнап подгоняется в коробку кодом (имена разной длины, шкала кеглей),
а не расставляется по координатам руками.

Заголовок и тэглайн набраны готикой Grenze Gotisch (SIL OFL), плиты лайнапа и дата узким гротеском: у имён кегль
крупный и готика читается, а дата обязана читаться в любом кадре. Шрифт афиши лежит в
`src/understav/gothic.js` в двух видах, потому что потребителя два: объёмный заголовок
читает `typeface.json` (`node tools/gen/ttf2typeface.mjs <шрифт.ttf>
src/understav/fonts/<имя>.typeface.json`), а трафареты рисуются на canvas и требуют файл
шрифта в браузере (`public/assets/fonts/`, лицензия там же).

Лайнап набирается одним кеглем на все имена, по самому длинному из них: разный кегль
читается рангом, а ранга у имён нет, есть только разная длина ников. Хедлайнер выделен
цветом, а не размером.

Заголовок не мигает в такт: жар волной идёт по прожжённой фаске и изредка срывается дугой.
Ровный пульс в бит читается гирляндой, а не раскалённым железом. Яркость эмиссии
выравнивается по светлоте цвета — блум берёт по яркости, и красная плита без этого не
доходит до его порога.

### 3. Постобработка: `src/understav/effects.js`

```js
createEffects({ renderer, scene, camera }) -> {
  render(dt, elapsed, motion),   // motion: { speed, turn } из модуля камеры
  resize(width, height),
  controls,                      // { имя ручки: { get, set, min, max } } для пульта
}
```

Эффекты ведутся данными сцены, а не картинкой: сила искажения от глубины, хроматика и
смаз от настоящей экранной скорости камеры.

### 4. Страница, пульт и съёмка

Файлы: `understav.html`, `styles/understav*.css`, `src/understav/main.js`,
`src/understav/camera.js`, `src/understav/record.js`.

```js
createCameraRig({ camera, bounds, rng }) -> {
  setMode(name),                 // 'still' | 'orbit' | 'descend'
  update(dt, elapsed),
  motion,                        // { speed, turn }, читается постобработкой
}
```

Пульт: сид, режим камеры, кадрирование (1:1, 9:16, 16:9), сила эффектов, запись в файл.
Отсчёт дней до события считается из даты, а не вводится руками.

## Живность зала: стая летучих мышей

Мыши это не украшение, а то, что делает свод обитаемым и читается силуэтом на розе.
Требования те же, что ко всему остальному в этой сцене:

- Вся стая это один вызов отрисовки: `InstancedMesh` с крылом в вершинном шейдере, а не
  меш на мышь и не пересборка геометрии в кадре.
- Траектории и взмах считаются от `elapsed` и сида: снятый отрезок обязан повторяться, а
  запись покадрово давать тот же кадр.
- Коробка типографики остаётся пустой, как и для всего зала: мышь не пролетает сквозь
  буквы. Летают они под сводом, вокруг розы и между пилонами.
- Взмах живёт в своём темпе, а не на бите: стая, машущая в такт, читается как гирлянда.
- Место в бюджете: не больше одного вызова отрисовки и десяти тысяч треугольников на всю
  стаю, тени мыши не отбрасывают.
