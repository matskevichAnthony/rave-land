# Ретаргет танцев Bandai Namco BVH → риг персонажа

## Итог

Два mocap-клипа танца перенесены на 17-костный риг из `rig.blend` и
экспортированы в `dance.glb` (меш + риг + NLA-треки):

- **Dance** — 200 кадров, 6.67 с @30fps, вырезан из
  `dataset-1_dance-short_normal_001.bvh`, кадры 1531–1731 (51.0–57.7 с тейка);
- **DanceLong** — 484 кадра, 16.13 с @30fps, из
  `dataset-1_dance-long_normal_001.bvh`, кадры 2057–2541 (68.6–84.7 с тейка).

## Метод

Rest-поза BVH-скелета (кости вдоль ±X, «лежачая» иерархия) не совпадает с
нашей, поэтому локальные ротации не копируются. Вместо этого
(`retarget_dance.py`):

1. **Семплирование**: BVH импортируется (`global_scale=0.01`), для каждого
   кадра снимаются мировые кватернионы всех маппленных костей.
2. **Калибровка**: первые ~2 с тейка — статичная стойка (взят кадр 10). Для
   каждой пары костей строится постоянный оффсет: минимальный поворот от
   rest-направления нашей кости к мировому направлению кости BVH в
   калибровочном кадре (`rotation_difference`), помноженный на rest-ориентацию
   рига. Разница rest-поз поглощается полностью, включая Shoulder_* (их вклад
   уже сидит в мировой ориентации UpperArm).
3. **Перенос**: желаемая мировая ориентация кости = мировая дельта BVH от
   калибровочного кадра × калиброванная ориентация. Пересчёт в локальные
   кватернионы — аналитически по цепочке
   (world = parent_world @ parent_rest⁻¹ @ rest @ basis), без constraint'ов и
   nla.bake — сразу батч-запись fcurves (LINEAR, ключ на каждый кадр).
4. **In-place**: горизонтальный дрейф корня убран; оставлены вертикаль hips
   (масштаб 0.83 = отношение высот таза) и высокочастотное покачивание таза
   (отклонение от скользящего среднего за 2 с) — без него танец теряет грув.
   Суммарного смещения по горизонтали нет.
5. **Пол**: у BVH стопа гнётся в Toes, у нас одна жёсткая кость до кончика
   носка — на носках носок уходил под пол (до −5 см). FK-расчётом носка и
   пятки на каждом кадре добавлен плавный (окно 9 кадров, циклически) подъём
   hips. После правки: min z носка −0.000/+0.007, среднее +0.020 (= rest).
6. **Луп**: точки обрезки — перебор (длина 5–11 с для Dance, 12–24 с для
   DanceLong) по минимуму взвешенной позо-дистанции (кватернионы + высота
   таза) на окне 5 кадров + штраф за перемещение; сегменты с низкой энергией
   движения (стойки в начале/конце тейка) отсекаются. Шов: последние 15
   кадров слерпятся к кадрам предыдущего цикла, последний кадр равен
   первому — луп точный и по позе, и по скорости.
7. Средний фейсинг сегмента развёрнут в −Y (лицом, как риг), клипы уложены в
   NLA-треки, меш дециматирован до 32k треугольников (как в исходном
   пайплайне), экспорт `export_animation_mode='NLA_TRACKS'` + force sampling.

## Маппинг костей

| Риг | BVH |
|---|---|
| hips / spine / chest / neck / head | Hips / Spine / Chest / Neck / Head |
| upper_arm.\* / forearm.\* / hand.\* | UpperArm_\* / LowerArm_\* / Hand_\* |
| thigh.\* / shin.\* / foot.\* | UpperLeg_\* / LowerLeg_\* / Foot_\* |

Shoulder_\* и Toes_\* отдельно не мапятся: плечи входят в мировую ориентацию
UpperArm, носки покрыты клампом пола.

## Проверка

- `verify.py`: контакт с полом (min/mean/max z нижней точки стоп), точный шов
  (|первый−последний кадр| = 0), содержимое GLB.
- В GLB две анимации ровно с именами `Dance` (6.667 с) и `DanceLong`
  (16.133 с), по 51 каналу. «Icosphere» в сцене после реимпорта в Blender —
  кастомная форма костей, создаваемая импортёром; в самом файле её нет
  (проверено по JSON-чанку GLB).
- Рендеры `dance-front/side-1..4.png`, `dancelong-front/side-1..4.png`:
  движение читается как танец, конечности не выворачиваются, скруток нет,
  в пол не проваливается.

## Известные дефекты

- Твист вдоль кости берётся минимальной дугой от калибровочной стойки:
  возможна постоянная ошибка скрутки предплечий/кистей (кисть — одна кость,
  пальцев нет; на дистанции NPC незаметно).
- Стопа жёсткая: на носках персонаж опирается «кончиком сапога», перекат
  стопы приблизительный; кламп пола слегка приподнимает таз в этих фазах.
- Шаги в сторону остаются под зафиксированным корнем — при активных
  перемещениях внутри сегмента возможен лёгкий футслайд (для игрового лупа
  нормально).
- `dance.glb` — сырой экспорт (~2.8 МБ) без postprocess-сжатия (webp,
  квантизация); при надобности прогнать `postprocess.mjs` из `_other/auto-rig`.

## Файлы

- `retarget_dance.py` — весь пайплайн (семплирование → ретаргет → луп → NLA →
  decimate → GLB → рендеры); `probe.py` — разведка конвенций; `verify.py` —
  проверки.
- `dance.glb` — персонаж с клипами Dance и DanceLong.
- `retarget.blend` — сцена с недециматированным мешем и готовыми экшенами.
- `dance-*.png`, `dancelong-*.png` — контрольные рендеры.
